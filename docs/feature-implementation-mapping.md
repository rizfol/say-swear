# Stage 2 Feature-to-Implementation Mapping

This document follows the Stage 2 traceability requirement in `Project-Instruction.pdf` (sections 11 and 20). Feature, use-case, and sequence identifiers retain their Stage 1 traceability. The original design is preserved in the [Stage 1 report](stage1-report.md) and [archived UML](uml/stage1/). The [current class diagram](uml/class-diagram.puml) and current use-case/sequence diagrams retain the identifiers and describe the implementation.

**Latest presentation change:** [D19](design-changes.md) changes F01's CLI display to an in-place, resizable game panel with a separate editable prompt and direct terminal launch. Quiet/redirected/unsupported-terminal output remains plain and nonperiodic. The full build passed 76 Java tests; packaged demo, piped-fallback, and native Windows ConPTY checks passed. The actual PowerShell quiet-launch check also passed: piped state/quit reached the installed application, exited successfully, and emitted no ANSI escapes. The earlier structured repeat memory extends F05/F08/F09 without adding an eleventh feature; D18 records `MovementIntent`, `lastMovement`, and `REPEAT_LAST`. F10 remains **Fall Detection and Start Recovery**, as changed by D17. Current UC06/SD05 show start recovery; their archived originals preserve the checkpoint design.

**Current verification:** repeat support passed **73 ordinary Java tests**, **nine bridge tests**, packaged demo/live CLI, and **28 CPU model cases**. CPU model requests used a **60000 ms diagnostic cap** and live CLI used **30000 ms**. The updated **2000 ms GPU burst gate has not been rerun**; all seven current diagrams rendered and the class layout passed preview/geometry checks. The 14 archived original files were hash-verified. Earlier checkpoint-removal, GPU model, ASR, and GUI results remain historical evidence in [validation](validation.md). Student code/usability review and real microphone/gameplay validation remain outstanding.

All implementation links below identify existing files. A passing deterministic or demo-model check does not establish real-model interpretation quality. The recorded 73-test and CLI results predate D19; they do not establish terminal redraw/editing behavior.

## Verification evidence

The current repeat update passed 73 ordinary tests, nine bridge tests, 20 unchanged baseline plus eight repeat/history CPU cases, and packaged demo/live CLI checks. Their diagnostic deadlines and the outstanding updated GPU burst check are recorded in [validation](validation.md). The following 63-test, GUI/ASR, and GPU timing evidence predates repeat support and is preserved as history.

[CliViewTest.java](../src/test/java/com/sayswear/view/CliViewTest.java) passed all four checks for shared-state/map fidelity, scripted-mode event visibility, periodic-output throttling, and raw line/EOF handling. The 63-test ordinary run also passed game/control/controller, agent, HTTP-adapter, demo-parser, and fake-hardware voice-service checks. Seven [SemIf bridge tests](../tools/semif/test_server.py) passed. [JavaFxSmokeTest.java](../src/test/java/com/sayswear/view/JavaFxSmokeTest.java) passed against an actual scene; [SherpaNativeSmokeTest.java](../src/test/java/com/sayswear/voice/SherpaNativeSmokeTest.java) passed with the real ASR model. [LiveSemIfTest.java](../src/test/java/com/sayswear/agent/LiveSemIfTest.java) passed 20 isolated cases and the four-partial burst. The [packaged CLI check](../scripts/check-cli.py) passed with the real model and explicit demo model. Commands and limitations are in [validation](validation.md).

The [DemoDecisionModel](../src/main/java/com/sayswear/agent/DemoDecisionModel.java) is a deterministic demonstration parser. It can exercise application wiring without a live model, but its success cannot establish SemIf/Qwen integration, speech-recognition quality, or agent reliability.

The final 20 isolated model cases used a 15-second diagnostic deadline and took 242.2–503.1 ms. The separate real-agent burst returned its latest correction after 990.7 ms within the actual 2000 ms budget. These finite samples do not guarantee general interpretation accuracy or microphone-to-gameplay latency. Manual microphone/gameplay and human review remain outstanding; Stage 3 KUMA evaluation is a separate deliverable.
